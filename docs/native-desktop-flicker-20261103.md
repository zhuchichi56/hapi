# Desktop 对话闪回排查 · 2026-11-03

已复现并修复。已核对的“Codex Orchestra｜任务总控”最近消息仍在原始会话文件中；故障来自读取与显示回退，未发现该样本消息被删除。

## 原因

同一个对话有实时 owner 快照和 read_thread 备用历史两条读取路径。实时订阅短暂缺失时，旧代码最多等待400毫秒（历史缓存存在时不等），而建流最多需要2500毫秒，因此会提前返回较短、较旧的备用历史。网页直接用该结果替换当前内容；实时快照回来后又换回最新内容，形成 A/B 闪回。共享4条订阅的旧淘汰顺序会挤掉近期读者，使问题更容易出现。订阅暂缺的每次具体诱因未逐次追踪，不能把所有断线归为同一网络故障。

## 修复

保留近期读者的订阅；已确认实时来源的对话在重连期间不降级成备用历史；短暂缺口保留原内容，持续缺口明确报读取错误；历史请求完成时再次核对是否已收到实时快照。原 App 真正编辑、回退或裁剪后的快照仍然接受，不靠消息数量屏蔽真实更新。

只更新MacBook桥接模块并由既有原App follower接管宿主；未替换Mini Hub、重启原App或模型任务、发送或重放用户消息、改写会话文件。部署前保存模块备份，生产SHA256：054422f0d4f4850ae1da0d9da91c2e9a0344607283000ca074167284dfb88cae。

## 验证

- 线上修复前：独立浏览器41次轮询中，内容替换响应为8次备用历史、8次实时快照，反复切换；同id的两份视图分别约205与1434个内部条目（包括工具记录，不等于消息数）。
- 修复后：独立浏览器连续60次轮询，没有备用历史降级；8次内容更新均来自实时快照，其余保持原版本。期间新内容正常增加。

当前结论适用于已复现的Codex对话，未逐一审计全部历史会话或Claude对话。超过短暂重连窗口会显示读取失败并保留已有内容。
