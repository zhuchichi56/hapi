# Desktop 读取体验优化 · 2026-11-01

用户反馈新版加载和跟随感觉更卡。本次由主会话亲自测量、修改、部署和核验，没有委派执行器。原 Codex/Claude App、会话、模型执行和原生桥接均保持运行；只替换 Mini Hub 的前端构建。

## 原因与改动

- 普通文字已经通过 GFM parser 显示，却仍无条件请求 RichMarkdown，再替换整个消息 DOM。实际旧页面多加载 479,732 字节源码的模块（gzip 150,739 字节），还带两个小依赖。现在普通段落、表格、列表、引用、链接和小图直接保留同一渲染；代码围栏、数学和特殊协议链接继续按需加载原富渲染器。补齐基础列表和行内代码的原有样式，保留图片组件、中文加粗和原生引用规范化。
- 旧轮询在请求完成后再等 1,200ms。2 秒网络延迟下，读取间隔实际约 3.2 秒。现在成功的 active 读取把请求耗时计入周期，最少留 150ms，仍串行、不重叠；失败保持原退避，idle 保持 3 秒间隔，写请求不重放。
- 历史合并和展示使用稳定引用与 memo；输入草稿、刷新列表、重复健康状态不再重建历史分组。实际历史改变仍正常更新。
- 先读取会话，再初始化模型选择器以复用 snapshot 设置，避免首开多发一次 model-settings。模型目录按同一 API 调用身份缓存五分钟，并合并在途读取；失败清缓存、用户重试强制重新读，不缓存不同身份的目录，不缓存原生写入。

## 同条件实测

场景为正在运行的同一原生聊天，内容持续增长，不能当作冻结文本的严格性能基准。测量通过本聊天独立后台 Chrome/CDP 完成，未操作前台浏览器，未发模型消息。关闭缓存、绕过本浏览器的 service worker，模拟 200ms 网络延迟、512,000 B/s 下载和 4 倍 CPU 降速，各重复三次。

| 指标 | 修改前 | 修改后 | 判断 |
| --- | --- | --- | --- |
| 该普通会话加载的资源数 | 10 / 10 / 10 | 7 / 7 / 7 | 不再请求富渲染模块和两项依赖 |
| 同页资源 encodedBodySize 总和 | 663,680 B，三次一致 | 512,825 B，三次一致 | 减少 150,855 B，22.73% |
| 首条原消息可见时间 | 2338 / 2246 / 2231ms | 2682 / 2214 / 2228ms | 平均 2272±58 → 2375±267ms（样本 std），无可靠首屏提速证据 |

另在同一已加载页面模拟 2,000ms 网络延迟、同一带宽，修改前后各观测 13 秒实际请求：

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 读取开始间隔 | 3248 / 3244 / 3213ms | 2163 / 2159 / 2158 / 2166 / 2165ms |
| 间隔中位数 | 3244ms | 2163ms（缩短33.32%） |
| 最大同时读取数 | 1 | 1 |
| 本窗口成功完成读取 | 4 | 6 |

这两段是明确模拟条件下的浏览器测量，不是用户手机当前外网速度保证，也不代表模型推理提速。慢网时 active 请求数相应增加，但不重叠；unchanged 回包仍约百字节，idle/失败不升频。当前收益足以采用，保留更完整渲染和原生语义，不为首屏的未知收益继续改造通用 HAPI 路由。

真实公网验证：既有代理的原生 API 修改前3/3成功（2.649/1.906/1.634秒），修改后3/3成功（1.644/1.569/1.565秒）；本机公网直连修改前2次超时、1次6.529秒成功，修改后3次超时。网络路径波动尚在，未修改 Cloudflare/代理/DNS，不能把公网短样本差值算作本次代码带来的网络提速。Mac 桥接/经 Mini 转发的原生读取仍为毫秒级。
