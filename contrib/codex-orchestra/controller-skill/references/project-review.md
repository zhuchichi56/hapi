# 项目审查(项目组织者)

**项目审查 = 一份项目状态文件 + 事件触发的一次性无头运行。** 不是常驻聊天,所以没有要唤醒的会话、没有上下文膨胀,也不抢界面焦点。只有项目需要持续互动、且用户明确要求时,才为它开一个常驻聊天。

## 为什么这样设计

- 总控曾因同时承担"跟用户说话"和"逐条处理下级消息"而过载(心跳回合 81% 空转,上下文峰值约 253K token)。
- 判断类工作(验收建议、返工、停滞处理)可以在给定合同与证据时一次性完成,不需要长期记忆;长期记忆放文件。
- 无头运行已在本环境验证(Codex CLI 独立执行,T018;T022 的候选核验)。

## 项目状态文件

路径:`work/orchestra/projects/<projectId>.md`(`projectId` 取自 `project-catalog.json`,如 `console`、`urbanclaw`)。≤40 行,分两段:

- **代码生成段**(每次运行前由脚本重写,不手改):本项目任务表(任务号、状态、最近一次事件时间)、未确认回执数、越期/停滞项。
- **审查者维护段**:项目目标一句话;已做的决定(`decisionId` + 一句理由);约束与不可改项;下一步(≤3 条)。

## 一次运行做什么

触发:代码层发现本项目有需要判断的事件(新交付、受阻、越期、停滞)。输入:状态文件 + 相关任务的 `context` 短包 + 回执。输出写账本:

| 判断 | 动作 |
|---|---|
| 交付满足合同 | 写验收建议(`review` 候选),附证据路径 |
| 有缺项 | 写具体返工指令(1 个具体点 + 下一步),指向原聊天 |
| 受阻但可在授权内排障 | 写排障方案;能直接做的做,不能做的升级 |
| 需要资源或跨项目决定 | 上报 Root:**要资源** |
| 需要用户决定且未被放权 | 上报 Root:**需要你**(问题+推荐+代价+期限) |
| 同一冲突已升级两次 | 上报 Root,由 Root 给用户一条带推荐的选择 |

运行规则:只读为主;不改线上服务、不直接找用户、不处理其他项目;跑完即退,不等待;产出只含结论和引用,不转述原文。

## 上报格式(只有四类)

- **需要你**:问题 · 推荐 · 代价 · 期限
- **成果**:要求 → 做了什么 → 一图或一例 → 验收结论
- **卡住**:卡在哪 · 已试过什么 · 需要什么 · 期限
- **要资源**:要什么 · 多久 · 影响

## 何时设立

一个项目同时有 ≥3 个活跃任务时,设立它的状态文件和审查运行;少于 3 个由 Root 直接处理,避免为小项目增加管理成本。试点:`console`(总控台)。
